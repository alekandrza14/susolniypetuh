MYENGINE R23 — РЕГИСТРАЦИЯ ИГРОКОВ НА САЙТЕ

ЕСЛИ ВХОД ВЛАДЕЛЬЦА УЖЕ РАБОТАЕТ
1. Замени файлы существующего репозитория сервера файлами из
   MyEngine_PlayerIdentity_Server_R23.zip. app.py остаётся в корне.
2. Обнови существующий сервис Render (Deploy latest commit, если автоматическое
   обновление выключено). Используй прежнюю базу DATABASE_URL и прежние значения
   OWNER_*, GATEWAY_TOKEN_HASH, OTP_KEY, PUBLIC_BASE_URL, SMS_ENABLED, SMS_PROVIDER.
   setup_owner.cmd заново запускать не нужно. Новый сервис и новая база не нужны.
3. Открой https://АДРЕС-ТВОЕГО-СЕРВЕРА/moderation.
   Введи тот же номер и пароль владельца, с которыми уже подтвердил авторство.
4. Выбери режим и нажми «Сохранить настройки»:
   — Закрыта: только ранее зарегистрированные игроки.
   — Свободная — после SMS: укажи ID товаров, например base, demo.
     Эти товары разрешается зарегистрировать бесплатно после SMS-проверки.
   — По заявке — с моим одобрением: новые игроки попадают в очередь.
     Открой заявку, проверь данные, нажми «Одобрить» или «Отклонить».

При первом обновлении регистрация ЗАКРЫТА. Существующие игроки, сертификаты,
пароль владельца и настройки телефона сохраняются. Таблицы новых заявок
добавляются автоматически. Android-приложение R21 подходит без переустановки.
Настройки регистрации хранятся в PostgreSQL и переживают перезапуск сервиса.

КАК ЭТО ВЫГЛЯДИТ ДЛЯ ИГРОКА
В обновлённой игре игрок выбирает сертификат. Если его ещё нет в реестре,
а регистрация открыта, браузер откроет /register с данными выбранного сертификата.
Можно также открыть /register напрямую и выбрать JSON-файл вручную.
Игрок вводит свой номер, необязательный email и комментарий.
В свободном режиме приходит SMS. Без правильного кода доступ не выдаётся.
В режиме заявок SMS на этапе подачи не отправляется; автор видит, что номер
ещё не подтверждён. После одобрения при входе из игры игрок подтвердит его по SMS.
После регистрации / одобрения игрок возвращается в игру, выбирает тот же
сертификат и проходит обычную проверку входа. Уведомление об одобрении по SMS
или email игроку не отправляется: статус можно проверить в открытой вкладке.
Если вкладка закрыта, достаточно позднее повторить вход из игры.

ПИСЬМО «ИГРОК ХОЧЕТ ЗАРЕГИСТРИРОВАТЬСЯ»
Это дополнительное уведомление автору в режиме заявок. Сама заявка всегда
сохраняется в кабинете, даже если почта не подключена или отправка не удалась.
1. В Resend получи API-ключ с правом отправки и подтверди адрес / домен отправителя.
2. В Environment существующего сервиса Render добавь:
   RESEND_API_KEY = твой секретный API-ключ Resend
   EMAIL_FROM = подтверждённый адрес отправителя, например games@your-domain.ru
   Указывай только email, без отображаемого имени и угловых скобок.
3. Сохрани Environment с обновлением сервиса.
4. В /moderation включи «Присылать мне письма о новых заявках», укажи свой email
   получателя и сохрани настройки. Это отдельный адрес от EMAIL_FROM.
Для тестового отправителя Resend действуют ограничения получателей самого Resend.
Секретный ключ вводится только на Render, не в игру, не в сайт и не в GitHub.
Статус «принято почтовым сервисом» означает принятие API, а не доказанную доставку.
Статус доставки проверяется у провайдера. Неудачное письмо можно повторить в
кабинете в течение 23 часов; повтор использует тот же идентификатор сообщения.
Почта идёт через HTTPS. SMTP-подключение на бесплатном Render не требуется.
Автоматические письма игрокам и произвольная рассылка не добавлены.

ПРАВИЛА ДОСТУПА
Регистрация не подтверждает оплату. Неподписанный JSON может создать сам игрок.
Не добавляй платные товары в список свободной регистрации, если не хочешь
выдавать их бесплатно. Для платных товаров используй заявки с проверкой покупки
автором либо отдельную интеграцию с подтверждёнными платежами.
Заявка действует 7 дней, SMS-регистрация — до 10 минут (сам SMS-код — 5 минут
для Android-шлюза), вход автора в кабинет — 1 час. Не более 5 кодов на заявку.
Ограничения подачи: 10 запросов / час с адреса, 5 / сутки на номер,
300 / сутки на весь сервер. SMS используют общий предел 100 / сутки сервера
и отдельный дневной лимит твоего Android-приложения.
Публичная регистрация не может занять ID / номер владельца, изменить чужой номер,
переназначить сертификат или заново включить заблокированного игрока.
Отключение регистрации не отзывает ранее выданный доступ. Для отзыва используй
существующую команду manage.py revoke (см. README_RU.txt).
Кабинет показывает до 100 самых старых ожидающих заявок; после обработки
нажми «Обновить», чтобы увидеть следующие. Истёкшие заявки доступа не дают.

ПРОВЕРКА ЭТОГО ОБНОВЛЕНИЯ
Автоматически проверены регистрация, роли владельца / игрока, очередь Android,
неверные коды, истечение срока, смена режима, конфликты сертификатов и сбои почты.
Проверки выполнены с локальной тестовой БД и заглушками провайдеров.
Реальные SMS и письма при тестировании не отправлялись.
Обновление само не публикует код на Render: обнови существующий сервер по шагам выше.
