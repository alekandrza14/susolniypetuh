MYENGINE R21 — SMS С ТВОЕГО ANDROID И ПАРОЛЬ ВЛАДЕЛЬЦА

БЫСТРЫЙ ПОРЯДОК
1. На Windows запусти setup_owner.cmd (нужен Python 3.11 или новее).
   Введи playerId владельца из своего сертификата, свой номер +кодстраныномер
   и придумай пароль длиной 12–128 символов. Ввод пароля скрыт.
   Пароль никуда не отправляется и не сохраняется открытым текстом.
2. В private-config появятся два приватных файла:
   render-secrets.env — значения для переменных окружения Render;
   phone-token.txt — отдельный ключ подключения Android-приложения.
   Это разные вещи: пароль владельца нужен на странице входа, ключ телефона
   нужен только приложению отправителя. Не публикуй private-config в GitHub.
3. Опубликуй ЭТУ папку сервера в отдельном GitHub-репозитории:
   render.yaml и app.py должны находиться в его корне. private-config,
   сертификаты игроков и телефонную базу туда не добавляй.
4. Render → New → Blueprint → выбери репозиторий. Шаблон создаст Python
   Web Service и PostgreSQL. DATABASE_URL подставляется из созданной базы.
   Внеси значения из render-secrets.env в Environment сервиса, а также
   PUBLIC_BASE_URL = настоящий https://имя-сервиса.onrender.com без пути.
   Пока адрес неизвестен, допустим https://example.invalid при SMS_ENABLED=false;
   перед входом обязательно замени его настоящим адресом и перезапусти сервис.
5. Зарегистрируй сертификат владельца и сертификаты игроков (см. ниже).
6. Установи MyEngine_SMS_Gateway_R21.apk на свой Android 8.0 или новее.
   На телефоны игроков приложение ставить не нужно.
   В приложении введи адрес сервера, номер SIM, ключ из phone-token.txt
   и дневной лимит SMS. По умолчанию лимит — 20 отправок в сутки UTC.
7. На Render установи SMS_ENABLED=true и SMS_PROVIDER=phone.
   На телефоне выбери SIM для SMS по умолчанию в настройках Android,
   разреши SMS и уведомления, нажми «Запустить отправку» и подтверди запуск.
   Дождись статуса «Подключён. Ожидаю задания».
8. В MyEngine: Коммерция → Сайт и кнопки → Проверка игрока / SMS.
   Вставь тот же HTTPS-адрес сервера и включи обязательную проверку игрока.
   Сохрани, перезапусти Play. На кнопке входа используй Player verified
   перед Load scene, либо готовый шаблон «Войти после проверки игрока / SMS».

РЕГИСТРАЦИЯ СЕРТИФИКАТОВ
Одинакового номера недостаточно: в реестре должны совпасть playerId,
productId и certificateId. Сначала автор проверяет покупку или выдаёт
разрешённый доступ разработчику, затем регистрирует сертификат.
На своём компьютере в этой папке установи зависимости:
  python -m pip install -r requirements.txt
Задай DATABASE_URL в окружении терминала: External Database URL своей
базы Render с TLS. Ограничь внешние подключения нужным IP в панели базы.
Пароль базы не записывай в GitHub, игру или Android-приложение.
  python manage.py grant --certificate "путь/сертификат.json"
Команда скрыто запросит телефон. Для своего сертификата укажи ровно
OWNER_PHONE; playerId в сертификате должен равняться OWNER_PLAYER_ID.
Для себя подходит сертификат разработчика «оплата не требуется».
Команда grant SMS не отправляет и банковскую оплату не подтверждает.

КАК ВХОДИТ ВЛАДЕЛЕЦ
Выбери свой сертификат в игре → на открывшейся странице введи свой номер →
появится поле пароля. Введи придуманный пароль, вернись в игру и нажми вход.
SMS себе не отправляется. Этот режим работает и при выключенном Android-шлюзе,
и при SMS_ENABLED=false, если сервер доступен и настройки OWNER_* заполнены.
Указывать пароль в сертификате, Blueprint, payments.json или APK не нужно.
Чужой playerId с твоим номером не получает такой доступ.

КАК ВХОДИТ ИГРОК
Сервер сначала проверяет запись игрока и сертификат, затем совпадение телефона.
После этого создаётся случайный шестизначный код сроком до 5 минут и задание
для твоего телефона. Приложение отправляет одну обычную SMS с фиксированным
текстом. Только правильный код открывает доступ; принятие SMS оператором
или состояние «отправлено» не означает, что игрок подтверждён.
После успешного входа сессия действует до 12 часов. Игра всё равно проверяет
её через сервер при запуске и каждые 15 секунд; свежесть ответа — до 30 секунд.
Входной Blueprint проверяет вход в сцену, а не автоматически выгоняет из неё.

ПЕРЕМЕННЫЕ RENDER
DATABASE_URL — PostgreSQL; Blueprint подставляет внутреннее подключение.
PUBLIC_BASE_URL — действительный HTTPS-адрес сервера без пути.
SMS_ENABLED — false для настройки, true для работы отправителя.
SMS_PROVIDER — phone (по умолчанию).
GATEWAY_TOKEN_HASH — отпечаток ключа телефона, созданный setup_owner.cmd.
OTP_KEY — ключ шифрования очереди и защиты кодов, созданный setup_owner.cmd.
OWNER_PLAYER_ID — ID владельца из его сертификата.
OWNER_PHONE — его номер, совпадающий с записью реестра и номером SIM.
OWNER_PASSWORD_HASH — соль и scrypt-хеш пароля, созданные setup_owner.cmd.
Все три OWNER_* задаются вместе либо все отсутствуют (тогда режима владельца нет).
Чтобы сменить пароль, можно получить новый хеш через setup_secrets.py в отдельной
папке/копии сервера и заменить только OWNER_PASSWORD_HASH в Render.
Для завершения старых сессий используй revoke-player, затем grant для своего
сертификата: одни только новые настройки пароля не завершают старые сессии.
После смены GATEWAY_TOKEN_HASH потребуется обновить ключ в Android.
После смены OTP_KEY старые ожидающие коды недействительны; запроси новые.

ОТЗЫВ ДОСТУПА
  python manage.py revoke-player --player player_id
  python manage.py revoke-certificate --certificate certificate_id
Команды деактивируют запись и завершают соответствующие сессии. После
повторного grant прежняя завершённая сессия не оживает: нужен новый вход.

ОТПРАВКИ, ФОН И СБОИ
Телефон отправителя должен иметь работающую SIM, связь и интернет.
Приложение работает как явно запущенная служба с постоянным уведомлением.
Есть остановка в приложении и в уведомлении. Входящие SMS, контакты и
звонки приложение не читает. Экран может быть выключен; CPU поддерживается
активным во время работы службы, поэтому лучше держать телефон на зарядке.
Прошивка/энергосбережение всё равно могут остановить процесс. После перезагрузки
запуск вручную: автоматического скрытого старта нет. При недоступном телефоне
проверка не становится успешной. Остановка не отзывает уже переданную оператору SMS.
Лимит устройства — 1–100 отправок/сутки UTC. Попытка учитывается до обращения
к модему, даже если оператор затем сообщил ошибку. Сервер: 1 SMS в минуту,
5 в сутки на игрока, 100 в сутки всего, 3 на сессию; 5 попыток кода на сессию.
Пароль владельца: 5 попыток за 15 минут на аккаунт, включая новые сессии.
Телефон считается доступным, если опрашивал очередь в последние 90 секунд.
При достижении лимита телефон перестаёт брать задания; уже принятые могут истечь.
Стоимость зависит от тарифа и получателей, лимит приложения считает попытки,
а не денежную сумму. Безлимитную доставку код не обещает.

Задание выдаётся телефону только один раз и помечается до отправки. После
сбоя отправка того же задания автоматически не повторяется. Это уменьшает
риск двойной SMS, но при обрыве между выдачей задания и отправкой код может
не прийти. Тогда игрок ждёт минимум минуту и заново открывает проверку из игры.
Старый код при новой отправке отменяется. При ошибке устройства можно
повторно выбрать сертификат; секрет браузера в localStorage не хранится.

ХРАНЕНИЕ
PostgreSQL хранит реестр, сессии и очередь. OTP в очереди зашифрован, его
отпечаток защищён отдельным ключом; после выдачи кода телефону шифротекст
удаляется. Android хранит ключ и журнал отправок через Android Keystore;
резервное копирование приложения отключено. Пароль владельца на Android
не хранится. Не передавай ключ телефона игрокам: это ключ доверенного отправителя.
Экспорт сервера из движка использует список разрешённых исходных файлов,
поэтому private-config, .env и локальные базы не попадут в экспортный ZIP.

RENDER
Сборка: pip install -r requirements.txt
Запуск: gunicorn app:application --bind 0.0.0.0:$PORT --workers 1 --threads 8 --timeout 40
Health check: /health. Используется PostgreSQL; SQLite — только в автотестах.
Free Postgres истекает через 30 дней. Для постоянного реестра нужна база
без этого ограничения и резервное копирование. Платный план автоматически
не включается. Free Web Service после простоя может запускаться не сразу:
дождись ответа /health и повтори вход. База и сервис этим архивом не опубликованы.

пароля владельца, новый шаблон сервера и экспорт APK; металл R20 сохранён.
APK собран Android SDK 35 для Android 8.0+, подписан v2/v3 и проверен apksigner.
Комплект — личная тестовая сборка, не публикация в Google Play.
Проверены серверные сценарии, браузерная логика и компиляция Android-кода.
Фактическая доставка через твою SIM, работа в фоне на твоей модели телефона
и production PostgreSQL на Render требуют проверки после настройки.
Автотесты расположены в tests/test_gateway_r21.py полного движка; SMS не отправляют.
Старый адаптер Twilio сохранён как опция SMS_PROVIDER=twilio; прежняя инструкция
в README_TWILIO_R20.txt. Для варианта phone аккаунт Twilio не требуется.
