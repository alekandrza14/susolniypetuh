MYENGINE R20 — СЕРВЕР РЕЕСТРА ИГРОКОВ И SMS

Этот архив — отдельный сервер Python для Render Web Service + PostgreSQL.
Он проверяет существующую запись playerId/productId/certificateId,
привязанный номер телефона и ответ Twilio Verify. Регистрации из браузера нет.
Платёжный сайт/каталог остаётся отдельным; банк здесь не опрашивается.
Сервер ещё не опубликован, настоящие SMS не отправлялись.

ПУБЛИКАЦИЯ
1. Распакуй ZIP в отдельный GitHub-репозиторий. render.yaml, app.py,
   requirements.txt и папка static должны лежать в корне репозитория.
   Не загружай туда сертификаты игроков, базу, телефоны или секретные ключи.
2. Render → New → Blueprint → подключи этот репозиторий.
   Шаблон создаёт Web Service и Postgres на free-планах.
   Для постоянного реестра нужна база без короткого срока жизни:
   Free Render Postgres истекает через 30 дней, затем без обновления тарифа
   удаляется после 14 дней льготного периода. Учти это до регистрации игроков.
   Никакой платный тариф этим архивом автоматически не включается.
3. Переменные окружения Web Service, только в Render:
   DATABASE_URL — внутренняя строка подключения PostgreSQL; Blueprint
                  подставляет её через fromDatabase.
   PUBLIC_BASE_URL — фактический HTTPS-адрес Web Service без пути,
                     например https://твой-сервис.onrender.com.
   SMS_ENABLED=false — оставь, пока провайдер и реестр не настроены.
   TWILIO_ACCOUNT_SID — AC… из своего аккаунта Twilio.
   TWILIO_AUTH_TOKEN — секретный Auth Token.
   TWILIO_VERIFY_SERVICE_SID — VA… созданного Verify Service.
   При первом создании до получения адреса можно поставить для PUBLIC_BASE_URL
   https://example.invalid, оставив SMS_ENABLED=false. После создания укажи
   настоящий адрес и перезапусти сервис; с заглушкой рабочая проверка не получится.
   При отсутствии аккаунта Twilio оставь SMS выключенным. Не используй
   фиктивные ключи для включённого режима.
4. Сборка: pip install -r requirements.txt
   Запуск: gunicorn app:application --bind 0.0.0.0:$PORT --workers 1 --threads 8 --timeout 40
   Health Check Path: /health. Ответ содержит status и smsEnabled.
5. В Twilio проверь Verify Geo permissions для страны получателей,
   доступность доставки, условия своего аккаунта и тариф. Бесплатные
   безлимитные SMS этот код не предоставляет. Не все страны/аккаунты
   обязательно доступны; при необходимости адаптер TwilioVerify заменяется
   другим провайдером с таким же send/check-контрактом.
6. Зарегистрируй игрока, затем поставь SMS_ENABLED=true и перезапусти.
   Первое открытие free-сервиса после простоя может требовать ожидания:
   открой /health в браузере, дождись ответа и повтори вход из игры.

РЕГИСТРАЦИЯ: ТОЛЬКО У АВТОРА
Установи зависимости на своём компьютере с Python. Задай DATABASE_URL
в окружении терминала: используй External Database URL из Render с TLS,
доступный только нужному IP. Не вставляй пароль базы в файлы проекта.
На сервере можно применять Internal Database URL из его окружения.

  python manage.py grant --certificate "путь/сертификат.json"

Команда скрыто запросит телефон формата +кодстраныномер без пробелов.
Сертификат должен иметь schema=myengine-license/v1, licenseStatus=issued
и точные playerId/productId/certificateId. Проверь покупку самостоятельно
ПЕРЕД grant. Для владельца игры допустима выдача разработчику без покупки.
Команда grant сама не отправляет SMS и не проверяет платёж через ЮMoney.
Повторный grant той же пары восстановит активность. Незаметно переназначить
существующий ID игрока на другой телефон или сертификат другому игроку нельзя.
Восстановление утраченного номера требует отдельной ручной проверки автора.

ОТЗЫВ
  python manage.py revoke-player --player player_id
  python manage.py revoke-certificate --certificate certificate_id

После отзыва проверка существующих сессий тоже отклоняется. Клиент обновляет
результат примерно раз в 15 секунд, свежесть ответа ограничена 30 секундами.
SMS_ENABLED=false останавливает новые SMS и новые сессии; для отзыва уже
проверенных аккаунтов используй команды выше.

ПОДКЛЮЧЕНИЕ К ИГРЕ
Коммерция → Сайт и кнопки → Проверка игрока / SMS:
укажи настоящий PUBLIC_BASE_URL, включи обязательную проверку, сохрани.
На кнопке входа используй шаблон «Войти после проверки игрока / SMS».
После подтверждения кода игрок возвращается в игру и снова нажимает вход.
После успешной проверки новая SMS не нужна до истечения 12-часовой сессии,
но онлайн-проверка сервера нужна при каждом запуске. Токены сессии приватны.

КАК РАБОТАЕТ API
POST /api/sessions: playerId, productId, certificateId, clientNonce.
  Только существующая активная запись. Ответ: verificationUrl с токеном
  браузера во fragment (#…), независимый pollToken и связанные ID.
POST /api/sessions/<id>/phone: Bearer browser token + JSON {phone}.
  Только номер из реестра; после явного нажатия пользователем отправляется SMS.
POST /api/sessions/<id>/code: Bearer browser token + JSON {code}.
  Сервер обращается к Verify API, проверяет approved, телефон и service_sid.
GET /api/sessions/<id>: Bearer pollToken; возвращает pending/verified/expired.
  Телефон и код в ответ не попадают. Токен браузера не подходит для этого API.
Ограничения: до 3 отправок на сессию, 1 на минуту и 5 в сутки на игрока,
100 в сутки на весь сервер; 5 попыток кода на сессию. Лимиты фиксированных
временных окон. Неуспешные обращения к провайдеру тоже учитываются.
Сессия ожидания — 10 минут, подтверждённая — 12 часов. Реестр проверяется
при каждом запросе статуса. Секретные токены в базе хранятся как SHA-256.
Номер хранится в приватном PostgreSQL; OTP хранит и проверяет провайдер.
На странице нет сторонних скриптов, localStorage и публичной админ-панели.

ПРОВЕРКА ПЕРЕД ИСПОЛЬЗОВАНИЕМ
Автотесты с имитацией провайдера находятся в tests/test_identity_r20.py
полного движка. Они не отправляют SMS. SQLite используется только в тестах;
production app.py требует PostgreSQL и при отсутствии базы не открывает доступ.
render.yaml проверен локально как YAML и по структуре документации;
реальный деплой, PostgreSQL и доставка SMS ещё требуют проверки в твоём аккаунте.
Для реального пробного SMS возьми собственный зарегистрированный номер.
